# Touka

## Agreed product scope

A general-purpose remote agent, not a coding-only bot. Pi Durable owns the execution loop, pi-ai owns model access, and the Cloudflare Agents SDK PiHarness/Lifecycle runs it durably in a Durable Object. Slack mentions, GitHub bot mentions, Discord interactions, and authenticated Webhooks can initiate work. Touka is headless. Coding workflows stop at pull requests; deployment operations are out of scope. Cloudflare OS is explicitly not a reference implementation or parity target for this mission.

## Architecture decisions

- Run one agent Worker in `server/`, without a Web UI or authentication database. Retain Vite+ independently of the removed Web framework: root dev/build tasks delegate to `server`, and root configuration owns Vitest, formatting, linting, and type checks. Preserve Vite aliases/overrides and the server's lazy Cloudflare Vite v2 beta plugin. `server/cloudflare.config.ts` uses `cf/config`; the project-local cf CLI and plugin beta versions are pinned. Every server secret is declared there, because `.dev.vars` only supplies declared names. Local startup is `vp run dev`, not a separate Node/Miniflare launcher. Test fixtures run real workerd/SQLite/HTTP boundaries.
- The agent core is transport-agnostic. It accepts session IDs, operation IDs and input. It neither imports Slack/GitHub payload types nor requires a `source` discriminator. Do not inject origin labels into model prompts.
- Connectors (`packages/connector-github`, `connector-slack`, `connector-discord`, `connector-mcp`) own service credentials, token lifecycle, resource authorization, data reads/writes and API errors/rate limits. They import neither Triggers nor server internals. Triggers (`packages/trigger-github`, `trigger-slack`, `trigger-discord`, `trigger-webhook`) own inbound signatures, actor allowlists, filtering, thread-to-session mapping, event dedupe, durable accept/ACK and result/reply orchestration. Tool wrappers in `server/src/tools/` expose Connector operations with persisted server-validated resource grants. An Event is data, not an executable ingress module. Server is the composition root; Tools use Connectors independently of the initiating Trigger. Ingress grants write only where policy says so: the GitHub Trigger gives allowlisted actors `github:<repo>:read|write` on configured repositories, never the `workflow` grant (files under `.github/workflows/`), and nothing merges or deploys.
- Use `slack-cloudflare-workers` in Trigger Slack for protocol verification and `slack-web-api-client` in Connector Slack for Web API operations. Verify its automatic ACK/lazy listener behavior: durable acceptance must precede successful acknowledgement; model work and reply retries stay in durable jobs, not an ephemeral lazy handler.
- Keep inbound GitHub trigger separate from outbound GitHub tools: a Webhook-started conversation may create a PR using the existing bot GitHub App.
- Hono's HTTP API is the control plane; authenticated DO WebSockets carry snapshots and execution events. Reconnection obtains a fresh snapshot, not a fictitious cursor replay.
- One Durable Object/root Pi conversation per session. Operation IDs survive client/provider retries. Use durable acceptance before acknowledging external events; do not run long model work inside the webhook response.
- Provider/model defaults come from operator server configuration; explicit authenticated session commands can select and persist any registered provider/model. Support pi-ai's provider registry and operator-defined custom providers/endpoints, not a hard-coded Anthropic/OpenAI/Gateway allowlist. AI Gateway is optional, never mandatory or an implicit routing layer. Credentials stay in server secrets, not chat text/browser storage. Resolve configured provider auth through pi-ai rather than a fixed list of secret names. Runtime-incompatible provider features must fail explicitly; no silent fallback. `server/src/models.ts` uses pi-ai `builtinModels()` plus server-only `MODEL_PROVIDERS` JSON (`ProviderConfig`) and the typed SDK `Provider[]` seam in `server/src/operator-providers.ts`. JSON supports three common compatible APIs; arbitrary SDK APIs/auth/metadata use native `createProvider()` in that operator module, without editing core. `authContext.env` resolves arbitrary own string Worker bindings; no fixed secret allowlist or ambient process/file credential lookup. Catalog exposes IDs/names/APIs/configured only. `vp test test/models.test.ts` proves Node pi-ai HTTP serialization for Groq/custom endpoints and real workerd selection persistence, not universal workerd transport compatibility or live LLM connectivity.
- Target a private team with workspace/repository/guild/actor allowlists, not public SaaS signup. The management API and Webhook require server-configured `TEAM_AUTH` bearer credentials and exact session allowlists, independently of external-resource/Tool grants. Unauthenticated users see no chat data. Authentication fails closed when configuration is missing. Origin metadata may exist in Trigger audit records, not in the core input schema.
- One thread maps to one Session DO/root Pi conversation, independent of the caller. Management listing includes only existing sessions in that caller's allowlist; no global discovery index is maintained. The `PiDurable` records each accepted operation's reply destination beside its Pi conversation; the `DELIVERY` Queue only schedules reply attempts. A separate infrastructure DO owns sandbox coordination.
- Discord uses discord-hono in its own trigger package, initially HTTP Interactions (slash command carrying task input) with durable accept before deferred ACK and durable response delivery. Raw mention MESSAGE_CREATE events require a Gateway consumer and are not implied by HTTP Interactions support.
- Side-effecting tools must enforce authorization outside the model and declare replay safety honestly. No arbitrary internet-fetch or host-shell tool with ambient credentials. A sandbox is the only place for generated executable code.

## Shared delivery verification boundary

The server discovers independent Trigger package exports; Slack uses the library's awaited `beforeAuthorize` middleware. GitHub inbound reply delivery and agent Tools share `packages/connector-github` and its per-environment scoped token cache. Generic session/control envelopes live in `agent-contract`; `trigger-contract` contains only ingress/delivery lifecycle contracts, with no service auth helpers. See [connections](docs/connections.md) for dependency direction and verification. Reply scheduling uses the `DELIVERY` Queue; its retry and redelivery behavior is a platform guarantee that local tests do not exercise (see `server/src/README.md#evidence`). External model/GitHub/reply services are fakes; no deployment or live-service evidence is claimed. A shared gate exposed cross-session snapshot-size calibration drift from generation timing metadata; exact UTF-8 limit checks now exercise the production encoder deterministically, while real WebSocket tests retain near-limit delivery and oversized snapshot/event closure. The exact-limit test rejects a `>=` mutation. The old interrupted fixture is absent; each current fixture is isolated and cleaned by its owning test.

## Headless management and migration

`server/src/index.ts` keeps Hono for management routing, bearer authentication, body limits, and mounting independent Trigger apps. Session creation, history, stop/retry, model selection, and the native Pi event stream remain available over the authenticated control plane. Input enters through Triggers, including `/triggers/webhook`. Session DO WebSockets authenticate independently; there is no trusted Web identity bypass or browser proxy.

The native Cloudflare configuration declares two SQLite Durable Objects, `PiDurable` (one Pi conversation per session, plus its reply ledger) and `SandboxContainer` (the per-session container; its outbound traffic goes through the `GitHubEgress` entrypoint, which alone holds GitHub credentials), a second Worker `touka-codemode` that runs codemode scripts,, and one Queue, `DELIVERY`, whose consumer is the same Worker. Nothing has been deployed, so no namespace history needs preserving. Lifecycle declarations replace the former migration array; after a native deployment the platform cannot return to that legacy flow. See [Cloudflare toolchain](README.md#cloudflare-toolchain). No deployment occurs as part of the toolchain migration.

## Delivery

The user stopped r5 worker orchestration because it was too slow. Continue implementation and verification directly in the current agent; do not restart the harness or spawn implementation workers unless asked.

MCP is an operator-configured Connector, not a Trigger. `connector-mcp` uses the official MCP SDK v2 Streamable HTTP client with fresh per-operation connections; Pi tools list/call only explicitly granted server tools. No second Agent/AI SDK execution loop. Endpoints and header-secret references live in `MCP_SERVERS`; resource grants use `mcp:<server>:<tool>`. Interactive MCP OAuth and legacy SSE/stdio are not implemented. See `packages/connector-mcp/README.md`.

Mission plan: `docs/mission.md`. Local tickets: `.r5/issues/`. Runtime task ledger: `.r5/ledger.jsonl` (not committed). All repository documentation, comments, issues, code, model prompts, and commit messages use English. Conversation follows the user's language. Keep changes within the agreed headless scope; add no speculative OS/gadget abstractions.
